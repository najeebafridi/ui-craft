# Where sources disagree, and what we chose

One rule per conflict, with the reason. The skill follows these.

| Topic | What sources say | Our rule | Why |
|---|---|---|---|
| Touch / click target | WCAG AA 24px; Apple 44pt; Material 48dp; Fluent 44 web / 48 Android | **24px hard minimum for any pointer target. 44px for touch screens and primary actions. 48 on Android-native.** Keep 8px between neighbouring touch targets. | 24 is the legal floor, but 44 is what fingers need. Two numbers, each with a clear job. |
| Body font size | Fluent 14; Carbon/Radix/Material 16; Apple 17; GOV.UK 19 | **16px default. 14px allowed for dense desktop tools (tables, admin, IDE-like). Never below 12px.** Mobile inputs 16px or more. | 16 reads well everywhere and stops iOS zooming into inputs. Dense pro tools really do need 14. |
| Spacing base | Fluent/Radix 4; Atlassian/Material 8; GOV.UK 5 | **4px base. Scale: 4, 8, 12, 16, 24, 32, 48, 64, 96.** Use 8-multiples for layout, 4 for small inner gaps. | Most systems land on this set; one fixed scale stops "random 13px" spacing. |
| Corner radius | Fluent 4; Atlassian 6; shadcn 10; Material pills; Uncodixfy max 12, no pills; Taste: by domain | **Pick one radius set per product from the tone: sharp (2–4px) for finance/dev tools, medium (6–8px) default, soft (12–16px) for consumer. Inner radius = outer radius minus padding.** Pills only for tags, toggles and avatars, not every button. | Radius sets the mood. Choosing it on purpose beats both a hard cap and "rounded everything". |
| Contrast method | WCAG 2 ratios; Vercel prefers APCA | **WCAG 2.2 ratios are the rule: 4.5:1 text, 3:1 large text and UI parts.** APCA is an optional extra check. | WCAG 2 is the legal standard. APCA is still a draft. |
| Gradients / glass / glow | Uncodixfy bans all; Taste bans outside tech; frontend-design bans only clichés | **Flat colour by default. Allow one gradient or effect only when it is part of the brand, never as filler.** Never purple-to-blue "AI" gradients, glow shadows or glassmorphism on data screens. | These are the clearest signs of generic AI output. A rare, deliberate use can still be good. |
| Motion style | Uncodixfy: opacity/colour only; Taste: 2px lift; Vercel: transform + opacity; frontend-design: one big moment | **Animate only `transform` and `opacity`. 100–200ms for feedback, 200–300ms for panels and dialogs, never over 400ms for everyday UI. At most one "signature" motion per page.** No scroll fade-ins on every section. | Fast and quiet feels professional. These numbers match NN/g and web.dev. |
| Fonts | Uncodixfy: avoid Inter; Impeccable: avoid Inter-for-everything; frontend-design: deliberate choice | **Use the product's font if it has one. Otherwise choose on purpose: one family for apps, at most two for marketing pages. A system font stack is fine for tools.** Never pick a font just because it is the default. | Banning one font is arbitrary. What matters is that the choice fits the tone. |
| Loading indicator | Doherty 400ms; NN/g: nothing under 1s; RAIL 100ms | **Pressed state within 100ms. Show a spinner or skeleton only after ~300ms, then keep it at least ~500ms. Skeleton for full-page or section loads; spinner inside a button or small card; progress bar with % for anything over ~10s.** | Combines all three: instant response, no flicker, honest progress. |
| Skeletons per card | NN/g: page-level only; many systems: per card | **Skeletons for a page or a large section whose layout is known. Small widgets use a spinner.** | Many tiny shimmering boxes look busy and help nobody. |
| Required fields | GOV.UK: no asterisks, mark "(optional)"; Carbon: mark the minority; others: asterisk | **Mark the minority. Usually most fields are required, so mark optional ones with "(optional)".** | Text beats a symbol people have to decode. Marking the minority keeps forms quiet. |
| Validation timing | NN/g: on blur; Carbon/GOV.UK: on submit | **Check a field when the user leaves it, and again on submit. Never show errors while the user is still typing.** Live positive feedback (password strength) is fine. | Early but not nagging. |
| Disabled submit button | GOV.UK: avoid; Vercel: keep enabled until request | **Keep the submit button enabled. On click, show what is missing. Disable it only while the request is running.** | A greyed button gives no reason why it does not work. |
| Breakpoints | Material 600/840/1200; Fluent 480/640/1024/1366; Atlassian 480/768/1024/1440 | **640, 1024, 1440 for web.** Add more only where the layout actually breaks. | A small, common set. Content decides extra breakpoints. |
| Navigation | Apple: tab bar, no hamburger; Material: bar, then rail, then drawer by width | **Phone: bottom tab bar, 3–5 items. Tablet/small window: rail. Desktop app: sidebar 220–280px. Marketing site: top bar.** Hamburger only for secondary items. | Matches both Apple and Material once you split by screen width. |
| Dashboard style | Uncodixfy bans KPI-card grids; others use them | **Allowed: up to 4 KPI tiles, each with context (vs last period or target). Never a wall of identical cards with no comparison.** | Numbers with no context are the real problem, not the cards. |
| Pie charts | Datawrapper: OK for few slices; others: avoid | **Bar chart by default. Pie or donut only for part-of-whole with 2–4 slices.** | Bars are easier to compare. |
| Menus (ARIA) | APG role=menu for app menus; Inclusive Components: site nav is not a menu | **Site navigation = list of links (with a disclosure button on mobile). `role="menu"` only for app action menus.** | Both agree once the two cases are split. |
| Table density | Carbon 40px default (24–64 options); Material 52 | **Default row 40–44px. Compact 32px for power users. 56px+ only for two-line rows.** | Carbon has the best-tested numbers. |
| Shadows (v1) | Vercel: 2+ layers; Uncodixfy: one small shadow; Fluent: key + ambient pair | **Use 3 elevation levels at most: flat (border), raised (small two-layer shadow), overlay (larger shadow for menus/dialogs). In dark mode, show height with lighter surfaces, not shadows.** | A small fixed set stays consistent. Shadows barely show on dark backgrounds. |

## Version 2 decisions (premium craft, colour, psychology, platforms)

| Topic | What sources say | Our rule | Why |
|---|---|---|---|
| Borders vs shadows | Hobday: strong borders that contrast on both sides; Krehel: replace borders with a faint ring | **A 1px ring in the shadow for cards and menus; a real 3:1 border for form inputs.** | The ring is cleaner for decoration; inputs must be findable (WCAG 1.4.11). |
| Shadows in dark mode | Hobday: none; Krehel: keep layers plus a white ring | **Dark depth = lighter surface + ring. Soft shadows only under overlays.** | Shadows barely show on dark; the ring and surface step do the work. |
| Press scale | Rauno 0.9-0.96; Emil 0.97 | **0.97 by default (token), never below 0.9; deeper only for playful directions.** | Subtle feedback suits most products; the direction can change it. |
| Animation length | Rauno up to 200ms; Emil under 300ms; staged page reveals 600-800ms | **100-150ms feedback, 200-300ms overlays, 400ms cap in everyday UI. One staged reveal on a marketing page may run longer.** | Matches NN/g; keeps tools fast and lets one moment breathe. |
| Springs vs easing curves | Apple, Material Expressive, Motion: springs; Emil, NN/g: short eased tweens | **Springs for things that move or are dragged; plain fades for colour and opacity. No visible bounce in business UI.** | Springs keep gesture speed; overshoot on opacity looks broken. |
| Blur and glass | v1 banned glass; Apple and Windows use system materials; craft writers blur sticky headers | **Translucency only for chrome (sticky header, sheets, system materials). Never on content cards.** | It is a material for the control layer, not a decoration. |
| Gradients | v1: flat by default; craft sources: subtle lighting gradients | **A same-hue 2-4% lighting gradient is allowed on surfaces and solid buttons. Hue-spanning gradients only as one deliberate brand moment.** | Lighting reads as quality; washes read as filler. |
| Colour space | Stripe: CIELAB; Material: HCT; Linear, Tailwind, Evil Martians: (OK)LCH | **OKLCH, generated by `palette.mjs`, with WCAG 2 contrast solved per token.** | Native in CSS, perceptually even, simple to compute. |
| Hue shift in scales | Refactoring UI: shift hue as lightness changes; Radix, Stripe: keep hue | **Keep the hue fixed.** | Predictable and on-brand; hue shifts are a folk rule without evidence. |
| What colour "means" | marketing blogs: fixed meanings and big numbers; research: context-dependent, saturation and lightness matter most | **Set lightness and saturation for the feeling first; choose hue for meaning, category fit and difference. No fixed-meaning claims.** | Follows Valdez & Mehrabian, Palmer & Schloss, Elliot & Maier; the "62-90%" figure is a myth. |
| Dark mode by default | designers: dark is comfortable; NN/g: light reads better for most | **Offer both, follow the OS. Dark by default only where the direction calls for it (media, some tools).** | Preference and context, not a universal upgrade. |
| Fonts | v1: "choose on purpose"; anti-slop lists ban Inter | **Fonts come from the direction (16 pairs) or the brand. Inter is fine where neutral is right.** | Banning one default only creates the next default. |
| Persuasion | growth blogs: scarcity, urgency, hooks, decoys; regulators and research: often weak or deceptive | **Use only honest, well-supported effects (defaults that serve the user, real progress, real proof). Refuse the dark-pattern list.** | Evidence for the tricks is weak; the legal and trust cost is real. |
| Delight | Walter, Norman: design for emotion; NN/g: surface delight is secondary | **Deep delight first (saved effort); surface delight only at low-stakes moments; the more frequent, the plainer.** | Charm on a weak base annoys; repeated jokes wear out. |
| Native vs brand | Material everywhere; Apple and Microsoft: use the system | **The platform owns navigation, controls, gestures and the system font; the brand owns colour, content, voice and the signature.** | Redrawn chrome is the main cause of a fake-native feel. |
| Breakpoints | Android 600/840/1200; web v1 640/1024/1440 | **Keep 640/1024/1440 for the web; use platform size classes in native apps.** | Each is official for its own platform. |
